The merge uses `contact_id` as the identity key. It never uses email to identify someone.

For example, the supplied fixtures contain:

- `c-101`: Morgan, initially using `shared@example.invalid`
- `c-202`: Ari, also using `shared@example.invalid`

Those are different IDs, so both stay in the export. Morgan’s later row has a different email but the same ID, so it replaces Morgan’s earlier row without affecting Ari.

When an ID appears more than once, the merge:

1. Reads teams in the supplied order and contacts in array order.
2. Compares `updated_at` as actual instants using `Date.parse`. Comparing timestamp strings directly can give the wrong result with different timezone offsets.
3. Keeps the **complete row** with the newest instant, preserving its exact values.
4. Keeps the first encountered row if the instants are equal.
5. Leaves that ID in its original output position, even if its winning row appears later.

A JavaScript `Map` handles this: replacing a value for an existing key doesn’t move the key’s position. Winning rows are copied, so the merge doesn’t modify the inputs.

The seven regression tests cover:

| Test | What it verifies |
|---|---|
| Supplied fixtures | Shared emails stay separate; Morgan’s changed email doesn’t create a duplicate; newer names win; file order controls first-ID order. |
| Timestamp comparisons | Timezone offsets and fractional seconds are compared correctly; an older row encountered later cannot overwrite the winner; the complete winning row is preserved. |
| Equal instants | The first row wins within a team and across teams, including timestamps written differently but representing the same instant. |
| Exact IDs and frozen inputs | IDs remain case- and whitespace-sensitive; special strings work as keys; inputs aren’t mutated. |
| Empty inputs | Empty teams produce no contact rows and a header-only CSV. |
| CSV formatting | Column order, commas, quotes, carriage returns, newlines, and the final LF remain correct. |
| CLI | Running the command with the fixtures produces exactly the expected CSV and no stderr output. |

All seven pass. Malformed-row validation remains outside the contract; these tests assume valid IDs and timestamps.
