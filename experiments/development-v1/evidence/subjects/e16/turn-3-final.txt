The identity key is the exact `contact_id`. Email plays no part in deciding whether two rows belong to the same person.

For example, the supplied fixtures contain Morgan (`c-101`) and Ari (`c-202`) with the same email. They stay separate because their IDs differ. Morgan’s later row still has ID `c-101`, so it replaces Morgan’s earlier row even though the email changed.

For repeated IDs, the merge:

1. Compares `updated_at` as actual instants using `Date.parse`, so timezone offsets are handled correctly.
2. Keeps the **complete row** with the newest timestamp—name, email and timestamp together.
3. Keeps the first encountered row if the timestamps represent the same instant.
4. Leaves the contact at its original position in the output. Replacing its details doesn’t move it.

“First encountered” means file argument order, then row order within each file. IDs are compared exactly: `a` and `A` are separate IDs.
