## Why change the drafts before screening

A v1's “include each needed reason ... once” could be read as a hard anti-repetition rule even when a necessary caveat must accompany an updated recommendation. A v2 keeps necessary information and asks only whether filler, a recap or narration contributes understanding or decision value. This is still subjective and may overlap the stock host's writing instructions; it is a mechanism to test, not a guarantee. The relevance gate must not erase sources, uncertainty, limitations or a required standalone explanation just because they do not immediately change a decision.

B v1 already has the more natural conversational mechanism. B v2 retains its focus on changes and missing understanding, explicitly targets redundant introductions/conclusions, and uses the same audience/protection language as A. It does not forbid revisiting a premise or supplying a requested recap. “Include earlier context when needed for understanding,” requested depth and explicit user preferences constrain its incremental bias. A reader's confusion may justify considerable explanation.

Both versions preserve required content, detail and format in copy-ready text, quotations, files, code, documentation, structured output, tool traffic, memory and inter-agent messages. This is a categorical output boundary, not a list of case exceptions. Requested prose in chat can be a deliverable; location in a final message does not make it ordinary conversation. A full requested explanation to the reader remains inside chat scope but retains its requested depth. Both versions explicitly retain full work and verification, so the mechanism is editing communication rather than reducing research or task completion.

## Mechanism tests and key risks

| Candidate | Predicted improvement if useful | Failure signal or limit |
| --- | --- | --- |
| A v2: relevance gate | Removes an unnecessary recap, filler or routine progress interruption while keeping the answer, needed context and meaningful change clear. | A shorter reply that loses a caveat, explanation or useful expectation is a preservation failure, not a win. If only required cadence messages remain, interruption reduction may be constrained by the host. |
| B v2: incremental conversation | Later turns answer the new question or explain the changed situation without reprinting unchanged background; confusion triggers useful explanation. | Omitting needed prior context, repeating stale recommendations, or treating a requested comprehensive recap as disposable defeats the mechanism. First-turn improvements alone do not demonstrate the intended follow-up benefit. |
| Both | Ordinary chat improves while actual protected outputs and full work remain adequate. | The exclusion list is model instruction, not technical isolation. A copy-ready email or runbook shortened inside chat is still a protected-output failure. Tool/agent/memory scope remains unproven unless actually observed. |

The policies remain close to native clear-writing defaults. A natural absent baseline may meet both mechanisms already; ties would be informative, not an excuse to worsen the baseline or keep searching without a promising observed defect. Extra policy words and packaging convenience are costs/benefits separate from demonstrated communication efficacy. Neither draft promises measured comprehension, model diversity, desktop behavior, Claude compatibility or release readiness.

### Progress: reader benefit and host requirements

D1 has an opening update before the local read and no further discretionary progress. D2 turn one has an opening update in each arm and a diagnosis update. Example A v2: “The merge uses email as the identity key and compares timestamps as text. ### Actual work and preservation limits

All four D2 final merge files use the same stable-ID/`Date.parse` implementation; tests meaningfully cover shared/changed emails, complete rows, offsets, millisecond fractions, ties, ordering, immutable inputs, empty exports and exact CSV/CLI behavior. Every actual maintainer document and handoff retains meaningful detail and local commands. The D2 turn-three explanations correspond to their actual suites, rather than merely asserting a test count. The independent case/source audit records actual subject commands and all snapshots; I rely on it for broader per-turn byte preservation and execution findings rather than treating my final-file inspection as equivalent evidence.

The independent audit's shared sub-millisecond contract discrepancy remains material: all four implementations collapse distinct `.0001Z` and `.0002Z` instants to the same `Date.parse` value, so an older first row can win. A/e08 and absent/e07 disclose the millisecond limit in their handoffs, which is useful honesty but does not satisfy the unrestricted newest-instant contract. B/e09 and manual/e10 omit that edge. None is a full literal-contract work pass. The frozen probes' narrower passing behavior and the meaningful real tests remain true alongside this gap. No timestamp or export-specific rule is added to the policies, and the common code defect is not attributed to concision.

A v3 adds “Be concise,” admits background/examples/implementation/recaps only when requested or needed for understanding, explicitly says relevance to the wider task is insufficient, and stops after satisfying the request. This strengthens the current-question content gate; it is not a fixed length cap or a rule to give every answer one sentence. Earlier facts repeat when requested or necessary for that turn. It explicitly expands when a brief answer would mislead. Risk: an overaggressive incremental reading can assume context the reader needs restated; confused readers and requests for full recaps must get sufficient explanation.

Both retain the identical audience gate, protected-output categories, full work/verification, timely warnings/approvals and host precedence. Their discretionary progress gate now asks whether the reader needs action, has a blocker, or faces a meaningful expectation change. This is narrower than reporting any material discovery. A required update must still occur even when none of those conditions is present. Needed wait information remains a meaningful expectation change. A general finding that does not affect the reader can be deferred to the result. This is an instruction hypothesis to test against actual work, not authorization to suppress host rules.

Do not package the old manual text merely because it is shorter. Its screening outputs show largely the same background and follow-up pattern; no observed superiority here justifies replacing the experimental mechanism with it. If blinded assessments prefer it for specific reading benefits, retain that evidence in the selection decision. Packaging convenience is still separate from benefit over natural absent responses.
