# Retrospective automated assessment results

Routine evaluation now runs without owner example grading. The existing sample shows **no established communication improvement or regression from the enabled candidate**: all four blinded reviewers tied every reimbursement comparison. Three tied the detailed explanations; one slightly preferred enabled for its numbered failure cases and concrete transaction example. These are automated assessments, not measured human-comprehension improvements or release validation.

The original [criteria](pilot-criteria.md), [results](pilot-results.md), cases, policy and captured evidence are unchanged. The new [protocol](automated-evaluation.md), [independent challenge](assessment-v2-review.md), [artifact inspection](assessment-v2-artifacts.md) and [complete assessment archive](../experiments/assessment-v2/results/assessment.md) document this amendment separately. Production implementation, final marketplace identities and publication remain on hold.

## What was actually evaluated

Four fresh-context reviewers received neutral packets containing the four successful reimbursement runs (absent diagnostic, installed-disabled, enabled and minimal instruction), both detailed explanations, every captured progress message, actual generated code/tests/reports, standalone emails and historical command results. They also received the actual available child messages and saved report. They did not receive treatment labels, product identity, run IDs, policy text, prior judgments or each other's reviews. Each reviewed six reimbursement pairs, one detailed pair and four interleaved controls. Side assignments and pair order were reversed with two reviewers in each orientation. Full packets, templates, source mapping, raw judgments and hashes are archived.

The harness automatically prepares jobs, checks preservation and provenance, validates reviews, calculates calibration/ties/disagreement/order sensitivity and emits the report. This controller dispatched its four budgeted jobs through built-in agents; there is no embedded API or standalone model launcher in the script. Owner grading is optional. Future runs still require an authorized session allocation; this is not an unlimited unattended judging service.

## Communication judgments, calibration and order

Every reimbursement pair received four ties: absent versus disabled, absent versus enabled, absent versus minimal, disabled versus enabled, disabled versus minimal, and enabled versus minimal. No reviewer found a material difference in clarity, relevance, filler, repetition, unnecessary jargon or excessive updates. The disabled run's second update described a genuine additional command test, so it was not penalized merely for having another message.

The detailed comparison received three ties and one slight enabled preference. Useful technical precision and requested reasoning were retained rather than penalized as jargon or length. For context only, reimbursement wrappers contain 37–42 whitespace-delimited words; the detailed answers contain 1,371 absent and 1,624 enabled. These counts neither reward shortening nor establish a regression.

All four reviewers passed all four frozen controls:

| Control | Observed result |
| --- | --- |
| Remove R-103 only from the standalone email | All identify an essential omission despite the wrapper/report retaining it; ordinary-chat quality ties. |
| Add unrelated filler and three redundant updates | All retain information preservation and prefer the original for relevance/repetition/update quality. |
| Replace the necessary explanation with a fluent terse conclusion | All identify missing requested depth and prefer the detailed original. |
| Identical evidence under different aliases | All tie; no invented winner. |

All-reviewer and calibrated-only results therefore coincide. The 44 total pair judgments contain 35 ties, four left preferences and five right preferences, including controls. The weak detailed preference produces an orientation-sensitivity warning: one orientation splits between tie and enabled, while the other gives two ties. Different reviewers occupy the reversed orientations, so order and reviewer variation are confounded. This does not isolate order bias or prove it absent. Shared model/rubric biases and subtle defects beyond the obvious controls remain possible.

## Engineering corrections and verification

Independent prelaunch review caught and verified fixes for a contradictory numeric amount masked by a correct alternate representation, unsupported/empty evidence, source/fixture binding, and report-time freeze validation. Final offline checks passed ten detector/protection controls, six strict schema rejection tests and an unsupported-calibration rejection. The separate capture probe passed 17 synthetic checks and confirmed no plaintext directive was observed; it did not start a model subject.

All four review outputs initially used rich quote/issue objects where the frozen ingester required string arrays. Strict ingestion rejected them. A separate offline adapter preserved the complete raw originals, extracted exact quote strings and serialized whole issue objects without editing their content. One explicitly opposite-source quote in review 2 was relocated to its named candidate's evidence array; its original attribution was already explicit. Six format checks pass. Every field outside those representations, including statuses, preferences, dimensions, confidence and rationale, is asserted unchanged. Raw originals, conversion audits and initial failure records are archived. The packet hashes, frozen scorer, criteria and calibration thresholds did not change, and no reviewer was rerun for a better result.

The installed experimental plugin remains the four explicitly packaged runtime files, totaling 2,581 bytes in the prior pilot. This amendment changes no runtime package or policy and adds no runtime evaluator, network call or judging dependency. Its development files remain outside the installed package. This is a static packaging-boundary confirmation, not fresh packaged release validation.

## Accounting and next action

The original pilot used 11 sessions. This amendment conservatively counts three development collaborators and four fresh blinded reviewers: **18 of 24 combined**, with the one replacement reserve unused. Offline commands and format conversion created no new model conversations. No paid API/external judging service, credential copy or Claude command was invoked. Account-wide token/quota use was not independently metered in this phase; session accounting is not a monetary cost measurement.

Evaluation improved: routine checks and independent judgments are reproducible without owner grading, and deliberate information loss/filler are detected. No substantive product regression is established in the observed successful outputs, but no marginal communication benefit over these already clear baselines is established either. Unreadable helper instructions, human comprehension, missing comparators and broader behavior remain unverified.

The owner chose to keep native delegation verification pending and use existing output evidence. Do not repeat the blocked test or create another testing setup yet. Keep production implementation, final marketplace identities and publication on hold. Further routine development may use this assessment workflow within its authorized scope; changes requiring expanded access, sessions or production work need a concrete approval decision first.
