# SimplySay feasibility pilot results

Status: initial evidence complete; production implementation, final marketplace names and publication remain unapproved. Date: 2026-10-28.

## Recommendation

Keep the original portable policy and minimal instruction as experimental candidates. Codex's local native plugin route can load the policy automatically and omit it when disabled. The completed code/file/email and detailed-explanation tasks show no observed loss of required content. A completed enabled child report also retains the requested detail.

This does not establish a communication advantage over the baseline or minimal instruction. Human comprehension is unscored. The delegation baseline failed, so its comparison is incomplete; the child's incoming directive is not exposed by the inspected public history route. Hold production selection until the owner reviews matched examples and the remaining handoff uncertainty is addressed. Do not turn inherited policy text alone into a failure or broaden compatibility claims from these observations.

## What actually ran

**11 evaluation sessions: nine roots and two real native children**, including one interrupted child. No direct Claude model session occurred. One of the active 12 slots remains unused; 13 of the original 24 authorized slots remain unspent. No automatic further use is scheduled. Metadata queries, credential-free sandbox/guard probes, controller development and independent local file/function checks are not additional model subjects.

Root host: Codex CLI 0.163.0 on Windows, model `gpt-6.1-sol`, reasoning effort `low` (the advertised default, pinned identically across conditions). Every causal task used a fresh profile and neutral directory. Native MXC isolation was required after a fresh Windows profile initially downgraded workspace-write to read-only. Broad implicit temporary-directory writes were excluded. No legacy account setup, global configuration change, permission bypass, paid API fallback, or paid judging service was used.

The account-wide weekly meter was 47% used before model trials, 58% before the final task, and 59% afterward. It includes concurrent development activity and is not a pilot-only cost measurement. Per-root provider token counts are retained in the evidence; do not assume they include all child usage or infer a monetary bill from them. The pilot stopped with existing-plan quota remaining. All temporary sign-in copies were removed; see the [final cleanup record](../experiments/pilot/evidence/final-audits/cleanup-audit.json).

## Loading, inheritance and controls

Source-backed native install/list/config controls verified absent, installed-disabled and enabled states of the exact disposable package. Stored developer-message audits found the complete candidate once in each enabled human root, zero times in absent/disabled/minimal roots, and the minimal instruction once in its comparator. Startup-hook records bind the loaded policy hash to the actual native root session.

The enabled child history also contains the inherited candidate once. Its substantive report remains complete. This is evidence against treating inheritance alone as a scope failure, not proof of perfect isolation. The two stored matches in r08 are one root and one child history, not evidence of two injections into the same root.

A posttrial native uninstall from one completed enabled profile removed its candidate hook. Generated task-file hashes were unchanged, unrelated temporary settings stayed intact, and no auth copy was present. This was a control/removal check without a new model session; it is not a full upgrade/rollback or release lifecycle validation.

A fresh home still lists account-installed remote plugins. Effective profile configuration disabled app access and default plugins, enabling only the local candidate where intended. Source/account inventory and effective loading were kept separate; no connected-service tool use was observed in the task events. These are CLI results, not desktop/editor coverage or an assertion that all filesystem reads were physically isolated.

The prototype policy is 1,446 UTF-8 bytes (192 whitespace-separated words); the minimal instruction is 241 bytes (31 words). The entire uncompressed prototype payload is **2,581 bytes across four files**: plugin metadata 141, hook metadata 298, policy 1,446 and startup script 696. It uses one SessionStart Node process per observed enabled root, no extra model call, daemon or plugin network request. Node is a runtime prerequisite; it was already installed here. Host model tokens still increase with instructions; no zero-overhead claim or measured latency advantage is justified. The guard and evidence exporter are controller-only development tools.

## Diagnostic amendments and contrary evidence

The original protocol, cases, criteria and policy hashes are preserved. [Windows diagnostic](pilot-sandbox-diagnostic.md) records the r01 failure, zero-model probe and separately allocated r09. [Delegation diagnostic](pilot-delegation-diagnostic.md) records the capacity failure, V2 CLI omissions and namespace correction. Each amendment has its own parent manifest digest and controller revision; no original result or grading criterion was overwritten.

The first guard only covered a bare tool name. Actual V2 calls used `collaborationspawn_agent`; the marker did not exist in r07. Independent investigation corrected the earlier static generalization, and synthetic tests were extended. The corrected guard's actual r08 record and atomic claim confirm that it ran. This narrows earlier clearance and demonstrates why static approval was insufficient. The CLI's empty child list did not mean no child existed; local native history supplied the actual identity and public report.

The architecture-focused reference audit is complete within its approved scope: 117 files read fully and 304 explicitly excluded, accounting for all 421 tracked files. It is not a comprehensive review of the entire reference project. See [coverage and source-revision caveats](reference-audit.md).

## Unresolved before production

1. Human judgment of the matched examples, and evidence that packaging or the fuller policy adds value over native defaults/minimal instructions.
2. A matched inter-agent comparison with repaired controls/capture. Four sessions (two roots plus two children) would fit within the 13 remaining original slots, but require a newly recorded follow-up allocation and discussion, not silent reuse of the one-slot active reserve. Incoming directives remain opaque in the inspected public history route.
3. Resume, compaction, forks, co-installation, update/removal, machine callers/native structured responses, non-English tasks, broader work/research requirements and other model versions. Generated CLI JSON was checked; it is not a substitute for native machine-caller tests.
4. Codex desktop and other hosts. Claude execution is explicitly owner-run only; use the [standalone handoff](Claude_Pilot_Handoff.md). Its native Concise and automatic-versus-selected style comparisons remain unexecuted. Other integration candidates were not silently excluded.
5. Distribution and ownership decisions. Local hook feasibility is separate from the current public-directory hook restriction. No final catalog identity, license, repository publication or release approval follows from this pilot. The confirmed future target remains `Shilo/SimplySay`.

Production code and public claims remain gated. Keep runtime policy original and small, with native controls and only evidence-justified adapters; do not add levels, personas, rewriting services or a runtime evaluation framework to compensate for missing evidence.
