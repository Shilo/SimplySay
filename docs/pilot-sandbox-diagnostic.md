# First live failure and bounded sandbox correction

Recorded before the diagnostic model session. Frozen cases, criteria, and policy are unchanged.

The first absent task, r01, completed a model turn but failed to perform the task. Native turn metadata says `sandbox_policy: read-only`, despite the profile requesting workspace-write. The two attempted fixture reads were rejected by execution policy. No generated files or tests exist. Its output is retained, and it remains an infrastructure unknown for the style comparison, not a successful task or policy regression. One evaluation slot was consumed.

Pinned Codex 0.163.0 source explains that an unconfigured Windows sandbox backend can downgrade the requested workspace-write mode to read-only. Simply adding an explicit workspace-write flag would not solve that backend condition. Reusing the user's configured elevated setting in a fresh home could provision per-home sandbox accounts/state; unelevated legacy execution can modify ACLs. Neither was attempted.

Independent source review identified the existing native MXC backend as a fail-closed choice without account provisioning or DACL mutation. A credential-free native command probe first demonstrated fixture reading and in-task writing. The initial parent-directory write also succeeded because workspace-write includes implicit temporary-directory write grants by default. That finding is not evidence of an escape: it invalidated our initial probe assumption. A repeat with `exclude_tmpdir_env_var = true` and `exclude_slash_tmp = true` succeeded on the required three checks: fixture read, inside write, and parent write denied. The profile contained no auth cache. No new service, administrator setup, global setting, paid API, or model session was used for these probes.

The active correction explicitly selects `windows.sandbox = "mxc"` and removes implicit broad temp write roots in every remaining matched condition. Root read access is still broad; this is not a claim of filesystem secrecy. Tasks and event review must confirm that subjects access only the synthetic work. If MXC is unavailable, it must fail closed; there is no legacy or permissive fallback.

The original launch manifest and r01 remain untouched. `launch-manifest-v2.json` records the parent digest, controller revision, unchanged policy/task/criteria hashes, and corrected environment. It schedules r09 as a **separately labeled diagnostic absent task**, spending one of the two diagnostic slots under the frozen earliest-material-defect rule. It does not silently replace r01 in results. Remaining planned cells use the same corrected backend; compare them with r09 only with this correction clearly disclosed. Total possible subject use is now 11 planned/diagnostic sessions plus one remaining reserve, inside the 12-session active ceiling and 24-session owner cap.

Old prepared-but-unlaunched profiles are retained as preflight evidence; their temporary auth copies must be removed before abandoning them. New cells use fresh opaque directories. No grading criterion or behavior policy is being tuned in response to results.

Primary source paths inspected by the independent reviewer: `config/src/config_toml.rs` (Windows downgrade), `core/windows_sandbox.rs` (legacy setup selection), `mxc-sandbox/src/{lib.rs,windows.rs,native.rs,policy.rs}` (native path and `allow_dacl_mutation: false`), and `protocol/{models.rs,permissions.rs}` (implicit temp write grants), all at [rust-v0.163.0](https://github.com/openai/codex/tree/rust-v0.163.0/codex-rs). Native probe evidence is retained in the disposable controller directory and will be sanitized into the pilot results.
