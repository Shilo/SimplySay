# Desktop comparison: isolation remains unestablished

2026-10-29. Narrow read-only feasibility check after the unit 5 independent diagnoses. **Zero new model conversations/turns, installations, sign-in copies or preference changes.** This is not an actual desktop behavior test or a repeated backend loading check.

## Evidence inspected

The available create-chat tool schema supports existing local projects or projectless directories, with model/effort and prompt fields. It exposes no disposable credential/configuration profile or per-chat plugin-state control. Tool use also requires an explicit request for a new user-visible chat; the generic sub-agent/experimental authorization is not used to bypass that condition. No chat/project listing or creation was invoked and no personal-project content was accessed. The uninstall tool cannot supply an isolated installation mechanism.

Existing records already distinguish the actual desktop originator/context from the research app-server client. They share the pinned backend/model/effort in the observed metadata, not a demonstrated complete wrapper/history/tool/preference composition. Supported backend delivery remains established; no loading probe is repeated and no different originator is impersonated.

A targeted official-documentation search and page retrieval supplements only the desktop-isolation gap:

- [Developer settings](https://learn.chatgpt.com/docs/developer-settings) describes configuration shared by app/CLI/IDE agents and one-run CLI overrides. Shared configuration is a reason to avoid an experimental change in the personal profile; it is not a clean-profile desktop test.
- [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic) documents trusted project overrides and profile precedence. A trusted project can have its own settings, but that alone does not establish absence of inherited global instructions, memory, plugins or app preferences.
- [Environment variables](https://learn.chatgpt.com/docs/config-file/environment-variables) documents CODEX_HOME for CLI, IDE, app-server and installers. That table does not establish full desktop UI isolation, and is not permission to infer it from the already-successful backend profiles.
- [Plugins](https://learn.chatgpt.com/docs/plugins) documents app/CLI plugin installation and controls, without establishing the isolated absent/enabled/disabled desktop configuration needed here.
- The [Windows desktop page](https://learn.chatgpt.com/docs/windows/windows-app) was retrieved as part of this narrow check; no disposable-profile desktop route is verified by that retrieval.

These are current published documents, not a compatibility guarantee for the pinned 0.165.0-alpha.1.2 binary. No undocumented launch flag, UI injection, private request interception, personal-profile hook override or unrelated repository access was tried. No absence-of-documentation claim is promoted to technical impossibility.

## Result and next scope decision

The existing automated backend route is usable but is not newly reclassified as the desktop interface. A supported, controlled desktop route remains **unestablished**, rather than demonstrated impossible or automatically authorized to change personal settings. The current interface metadata and retrieved pages do not provide enough evidence to launch a clean desktop plugin comparison while preserving the agreed isolation.

Before live desktop testing, establish a supported way to bind a neutral test directory to its own configuration/auth/plugin state and capture actual messages/outputs without changing other chats. If that requires using the owner's normal profile or creating user-visible test chats, present that concrete access/setup choice first, with rollback and no personal-project access. No owner grading is required. Until then, retain desktop behavior and notification effects as unverified, and do not spend another backend repetition pretending it closes this gap.

This is one prospective route to more representative evidence. It does not explain away the latest progress-content regression, remove host communication requirements, prove that a better candidate exists, or establish that SimplySay is impossible. Production architecture and publication remain on hold.
