# Reference evidence delta: delivery, behavior and reader benefit

2026-10-29. Independent preparation task n03. This supplements [the existing research](communication-research.md); it does not repeat acquisition, change SimplySay policies, or establish a competitor winner. No script, installer, hook, benchmark, Claude command or model session was executed by this task. No policy text/persona/code-minimization rule was copied into SimplySay.

## Bottom-line finding

There is credible published evidence that instructions can change visible response style. There is much weaker evidence that the changed style improves the reader's experience, and no inspected reference establishes SimplySay's full ordinary-chat-only contract. Several headline comparisons use a different delivery path from the shipped plugin. A strong style change under a system-prompt override is not evidence that an installed hook reached the model under the host's unchanged requirements.

Two particularly useful findings were missing from the earlier summary: Ponytail's newer reply judges did **not** prefer its shorter replies over an untreated baseline; Caveman's current committed length snapshot has **no committed fidelity snapshot** and measures older rules than the current package. These limit what can be inferred from the references without dismissing their observed behavior.

## More useful than headline compression

### Ponytail's reply result is not a win against baseline

The October 7 report separately assesses replies with a blind, shuffled-order model judge and compares descriptions of the same diff to reduce differences in generated work. It reports replies 30% shorter than no skill, but the judge leans toward the longer untreated replies: 82 versus 106 preferences in actual-work pairs, with seven ties and p=.09. The same-code comparison is also not significant. It does prefer the new Ponytail version over its predecessor. This supports neither a baseline communication win nor a human-comprehension claim. [Pinned result](https://github.com/DietrichGebert/ponytail/blob/134b8e1a3a8078302b8ba77f86626c0802b2a6db/benchmarks/results/2026-10-07-agentic.md).

The inspected `answer.py` separates accuracy, coverage and clarity and tests whether a grader rejects an incomplete terse answer, a false answer and an overlong essay. That principle is useful. Its two-stage synthetic-reader/grader workflow adds model calls and still measures model assessments, so importing that machinery is unnecessary. Reuse SimplySay's existing blinded review and improve its realistic controls instead. The source's coverage definition is broad; SimplySay essentials must continue to come from the actual request.

### Outside Caveman evidence establishes feasibility, not SimplySay efficacy

JetBrains reports a paired SkillsBench comparison using installed skill loading plus an explicit activation reminder, on headless Claude Code/Sonnet 5/low effort. At scale it reports 8.5% fewer output tokens and no statistically detectable task-score difference across 82 full-run pairs. It also reports clear style transfer. This is useful feasibility evidence, but forced activation is a second intervention, no significant difference is not an equivalence proof, and task tests do not measure whether humans understand the chat more easily. It does not validate automatic activation or current SimplySay behavior. [Primary report](https://blog.jetbrains.com/ai/2026/07/speak-to-ai-agents-like-cavemen-tosave-tokens/).

The CAVEWOMAN paper's abstract reports eight models/five datasets with separate input/output compression conditions. It distinguishes task accuracy, realized cost and agreement with unconstrained reference text. Some correct outputs lose agreement with their reference; the authors report checks beyond length differences. **Inference for SimplySay:** passing a task-answer check can miss lost explanatory content. The abstract does not establish human readability, an installed plugin or chat-only work preservation. Only abstract/metadata were inspected here; paper code, full methods and results were not reproduced. [Primary paper](https://arxiv.org/abs/2606.24083).

Elastic's domain adaptation reports eight live Elasticsearch/MCP scenarios and response-size/technical-accuracy findings. Its two modes deliberately differ in explanatory presentation, and the article also reports an 88% success rate. This is a small domain case report, not a universal preservation result, ordinary-chat coverage or an independently reproduced SimplySay comparison. Do not import its raw-data presentation goal. [Primary article](https://www.elastic.co/search-labs/blog/elastic-caveman-ai-token-reduction).

## Alternatives and the next useful comparison

The previous inspection already identifies Say It Well as chat-oriented, Plain English as preservation-oriented, Humanizer as document rewriting, and Crisp as compression-oriented. No new model result was established for them here. Their instructions and static contract examples cannot fill the evidence gap by themselves. Whole-repository rereads or another catalogue search would not answer the current failure.

**Recommendation:** proceed with original SimplySay candidates and per-goal review rather than adding a competitor arm immediately. The reference evidence already makes style change plausible; the outstanding question is useful, scope-preserving change under our stock host. Judge realistic unnecessary explanation and truthful-but-unneeded progress, and preserve already-good and explicitly detailed answers.

If future candidates demonstrably load yet remain behaviorally unchanged, one targeted reference control could ask whether this same model/host can repair a genuinely confusing answer when explicitly asked, using an unmodified manual repair skill as a clearly separate comparator. It would diagnose model/task responsiveness, not installed-plugin efficacy. Do not add that arm automatically or silently convert it into SimplySay instructions. A broad unmodified Ponytail comparison would also change underlying implementation behavior; a Caveman persona comparison would introduce grammar/persona effects. Neither is a clean next test of SimplySay's goal.
