# Prospective goal-independent calibration

2026-10-29. This corrects future qualification in the existing development adapter. It does not change installed runtime, control samples, raw judgments, historical formal results or the definition of a communication benefit. Unit 3 remains mixed/unqualified under its frozen joint mode; no historical report was rerun to rescue it.

## Evidence and correction

Unit 3 reviewer 2 recognized the unneeded explanation on d2/d5, with the intended choice and specific quotations, but tied filler. On d5 its filler note assessed the identical final instead of the changed progress. These are substantive category/surface judgments, not formatting. Replacing them would change meaning. The former `every(expected.goals)` gate withheld explanation and repetition qualification because of filler disagreement, despite asking reviewers to assess goals separately.

Future manifests may explicitly select `goal_calibration_mode: independent-goals-v1`. Default `joint-v1` keeps the original joint behavior. Each expected style goal in the new mode retains the common preservation, intended overall direction and confidence requirements, and must independently supply its own intended goal choice and exact changed-surface evidence. No borrowing another goal's quotation. Filler tied/unknown/wrong-surface remains unqualified as filler; recognizing explanation does not repair it. Explanation, repetition and d3 clarity/jargon use their own unchanged required controls. Necessary-interruption/information and legacy four-control requirements are unchanged.

For the existing supplementary progress-payload screen, d5 records `payload_recognized` when at least one strict filler or explanation control passes. That screen can qualify broader progress sensitivity without forcing d5 update-count/repetition winners, which would be inappropriate when timing/count/final are identical. Own filler/explanation eligibility remains strict. Updates still need d1/d4 and repetition still needs its own d2 control. Unknown real-case judgments remain unknown, and no calibration result proves cadence compliance or desktop notification benefit.

The selected mode and actual manifest path/hash are stored in the freeze. Reporting verifies that the selected mode matches its hashed manifest; changed manifests/modes are rejected. Old cohorts retain their original source hashes and reports. Exact old scoring source is available in Git before this correction (for example 5aea5f4); do not silently substitute the new mode for historical replay.

Root and the independent continuing challenger executed the existing offline tool: **102 prospective-mode checks**, **51 default-mode checks**, and **61 joint-v2 checks** passed. These are synthetic checks, not new response/reviewer results. They test category disagreement in both directions, own-goal independence, common preservation/direction/confidence, wrong/shared/borrowed surface evidence, neither/one payload recognition, default joint rejection, frozen-mode/manifest tampering and byte-identical replay.

The independent challenger additionally compared default diagnosis outputs with the pre-correction source on eight synthetic fixtures: exact match. It verified all 287 locked files, all 33 archived review files across units 1–3, original controls/validators and both unopened sealed hashes. Its initial inline verification typo was corrected locally without file/model impact. Full evidence paths and source hashes are in reader-unit4-diagnosis.md. No new model session, grade, control or external service was used for these offline checks; the continuing diagnostic helper task is counted separately.

The change prevents unrelated category labels from withholding another goal's correctly supported evidence. It does not guarantee grader correctness, remove the failed goal's standard, reclassify unit 3 as successful, solve the remaining routine-check preview, or qualify the product for production/validation/publication. A future candidate and experiment still need a separately recorded purpose, fixed inputs and actual installed-plugin comparison.
