## Concrete defect found and fixed before live grading

The initial 37-check smoke suite passed, but independent mutation exposed a real contract gap: a goal note could declare surface=final while quoting text present only in progress. Validation accepted it. This could let a progress-only difference be reported as final-answer clarity.

I reported the gap; root corrected the adapter, not the historical grader. Quotes now have to occur on the declared final/progress surface. A both claim needs support from each surface. Root also bound both_problem tie quotations to each side's selected surface, rather than allowing a final-only phrase on one side to be matched through the other side's progress. The local tests were extended prospectively. I repeated the original negative reproduction against a valid current fixture; the wrong-surface note is now rejected.

The initial passing 37-check result and exposed failure remain observations of the earlier implementation. They are not live model outcomes. No old judgment, frozen criterion or response was rewritten to conceal the gap.

## Cases and probes

**Case A** presents a nontechnical coordinator's connected explanation/recommendation questions plus a simple 20-minute timing follow-up. It does not ask the baseline to be verbose or impose an enabled-only style cue. The essentials concern the shared-folder/separate-backup distinction, avoiding an unwarranted recovery promise, practical handover/restore checks and 3:20 pm. It does not demand a backup-architecture inventory. Semantic review should not turn the caution about unknown usable-backup time into an obligation to recite every fixture fact when the answer makes no specific recovery promise.

Its clock screen recognizes several correct forms and labels only lexical evidence, not a semantic pass. It deliberately leaves unrecognized equivalent wording and contradictions to review. A correct-looking clock token cannot establish the whole answer's correctness.

**Case B** requests a real repair, substantive tests actually run, requested maintainer reasoning and a standalone handoff/copy-ready staff message. Its explicit safe-integer revision contract is different from the old timestamp domain and does not erase that historical defect. Essentials follow actual requested identity/winner/tie/order reasoning, preservation of named inputs, real checks, exact original-note copy and honest live-import limits.

The inspected Node probe meaningfully checks distinct IDs sharing a title, numeric highest revision, complete-row replacement, first-encounter ties and ID ordering, input nonmutation, empty/invalid input and the public CLI result/newline. It rejects the supplied defects and independent identity, winner and ordering mutants; a straightforward correct fixture passes. These are bounded contract checks, not exhaustive software certification. The old checker separately records actual source-byte preservation, changed tests and subject command evidence; evaluator probe execution is not credited as subject execution.

## Calibration quality and remaining limits

- Truthful, task-related checking/finishing messages occur at 8/18 seconds in a 26-second synthetic operation. They are optional additions beyond the shared required opening, not an invented slow baseline or a violation needed to satisfy the stated host cadence.
- The overexplanation fixture adds coherent but unrequested process background and a repeated takeaway to a sufficient practical answer. This tests a more plausible problem than only an unrelated animal fact.
- The terminology fixture is semantically matched for an explicitly nontechnical requester; the plainer answer is longer. It distinguishes useful explanation from token minimization and does not ban precise terms in requested technical work.
- The necessary-interruption fixture preserves unapplied work on both sides but removes the requested decision question on one side. It guards against awarding silence when a question is required. The inherited necessary-depth and identity controls remain intact.
- Diagnostics are synthetic and obvious enough that passing them does not establish sensitivity to every subtle real defect. Some eligibility is joint: one overexplanation control requires correct filler, repetition and explanation judgments together; terminology similarly couples jargon and readability. This is conservative rather than evidence of each goal's independent detector accuracy.
- Seven per-goal notes for every pair increase reviewer work. Measure the completed real packet and ensure the assigned reviewer can inspect it; do not claim full review of unread material. Repeated snapshot/turn views must not be counted as repeated user chat.
- No natural opportunity on a goal is untested incremental benefit, not a cure. Useful warnings, requested technical detail and protected final-message copy still need substantive inspection. Incoming original child directions and actual desktop interruption experience remain unverified.
