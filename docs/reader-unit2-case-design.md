## Different source opportunity

[Case C](../experiments/reader-v1/cases/c.case.json) is a fictional community open-house door-scanner prototype. Its source is a normal implementation note: signed QR payload fields, a bundled public key, phone-clock validity checks, a cancellation snapshot, independent offline consumed-ID sets and an atomic online admission ledger. These are concrete engineering mechanisms rather than deliberately ornate prose. The source is written for maintainers; the first requester coordinates volunteers and does not write code.

That creates a plausible translation need without asking any subject to be verbose or bad. It is distinct from the earlier already-plain sync/backup notes and the synthetic search-index/cache terminology diagnostic. No competitor policy or candidate wording supplied its phrases. The facts are closed and fictional; no external lookup, live scanner, production change or generated code is needed. A baseline may still explain this source perfectly well; another satisfactory tie is a valid possible result, not grounds to manufacture a worse baseline.

Each essential is mapped to a clause of the actual request. C2 does not demand elliptic-curve internals, a code repair, key-rotation advice, a reconnect SLA or a deployment authorization the user did not request. C1 must not falsely imply reliable cross-phone rejection or current cancellation knowledge, but it need not rehearse the later worked examples. T-41 and T-99 are away from validity-window boundaries, avoiding an unnecessary inclusive/exclusive-expiry ambiguity. All times are on one fictional local demo day.

The C2 signature essential explicitly includes the positive guarantee: the trusted issuer signed the covered fields and they were not altered. It distinguishes that guarantee from current admission permission without demanding more cryptographic implementation detail.

The one fixture is `scanner-notes.md`, with its own raw UTF-8 SHA-256 in the case JSON. The existing preservation checker can bind its bytes at each turn. No output file or executable probe is required because the user requested explanations. Root may add a conservative C3 time-expression screen using the existing approach; unfamiliar correct expressions should remain unverified for semantic review, rather than being declared omissions. This task adds no new code oracle.
