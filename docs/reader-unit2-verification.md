## Policy challenge

The only substantive v1→v2 change replaces the old progress permission with: “Work without optional narration. Interrupt only for information the user needs before completion; omit preparation, routine-checking and finishing previews. Keep host-required openings and cadence brief.” The actor/action/consequence explanation mechanism and all final-answer, depth, uncertainty, warning, approval and protected-output clauses remain unchanged.

This is a distinct, falsifiable progress hypothesis: explicitly excluding routine previews may close a permission loophole in the more abstract before-completion gate. The exclusion names generic classes observed in existing records, without copying the study's facts or adding case-specific repairs. It is not a new explanation mechanism, and should not be described as a demonstrated whole-goal improvement.

Useful cautions remain. “Needs information before completion” requires judgment; a model may still mistake a truthful result for a necessary interruption, or suppress a useful warning. The explicit retention of warnings/approvals and host-required openings/cadence counters suppression, and d4/d5 supply opposing grading controls. The policy cannot override stock host requirements or interface notifications. Required presence must be retained; optional words inside that presence can still be unnecessary. Briefness cannot justify omitting required host content. No system-prompt replacement or removal of host requirements is proposed.

The scope boundary explicitly preserves required detail/format in copy-ready text, quotations, files, code, documentation, structured output, tool traffic, memory and inter-agent messages; it also requires completing work and verification. Ordinary human-directed chat is positively identified, with unclear audiences left unchanged. Actual audience framing must remain identical across matched conditions. Static wording establishes intent, not obedience or actual delivery of the new installed bytes.
