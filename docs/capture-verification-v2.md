# Delegation capture verification, retrospective amendment

Status: **the existing native V2 route does not provide observable parent instructions in this evidence. Do not spend a delegation retest on the same capture path.** This investigation started no model subject, child, thread or turn; accessed no sign-in cache or decryption key; and ran no Claude command. It is separate from the original pilot's criteria and results.

The actual child response is available. Both public r08 child messages recovered from the owned raw rollout match the previously exported messages byte for byte: 4,508 characters, SHA-256 `2593f6ce6911a8d77da7eb1ff5cb4355652739af0e24d85af64ed16d286c6c51`; and 117 characters, SHA-256 `ca5212e60f80c7f75e09c743b1b9cfd003ba50fe47f322e9cac8ee26d9c48bb9`. The actual parent spawn directive is opaque (1,124 characters); its later follow-up is opaque too (460 characters). The child rollout contains inter-agent metadata with a `trigger_turn` field, not a plaintext incoming request. Inherited root prompts cannot substitute for that request. Thus output preservation can be assessed, while original D2 remains **unknown**, including whether the parent added inappropriate style instructions.

## Evidence and zero-model checks

The [offline probe](../experiments/assessment-v2/capture-probe.cjs) inspects selected message-tool call shape and public assistant messages, exports lengths/hashes rather than opaque content, and excludes private reasoning, auth data and keys. [Machine-readable evidence](../experiments/assessment-v2/capture-verification.json) binds the two owned r08 rollouts, public messages and 13 pinned source files by SHA-256. Raw input paths remain local; no raw history was added to the repository. The existing API capture and artifact checks remain historical evidence rather than newly executed tests.

Executed `node experiments/assessment-v2/capture-probe.cjs --self-test`: 17 synthetic cases passed. The checks cover both bare and actual flattened V2 message-tool names, absent inputs, irrelevant events, privacy filtering and the observed opaque encoding. A synthetic plaintext input is explicitly classified as an unproven text candidate. The same extractor then scanned both existing r08 rollouts; both exported child-message hashes matched. No live hook transport, Rust test suite or new delegation run was executed. These tests establish offline extraction behavior and the observed missing capture, not plaintext access on a future live route. Recognizing the observed encoding prefix is not a general cryptographic detector.

## Why a hook logger alone does not close the gap

The previous budget guard recorded only tool name and child context; it retained no incoming `tool_input`. Adding that field without examining the native path would be another unproven capture claim. Pinned Codex `rust-v0.163.0` source provides a more specific explanation:

Those pages were fetched, but the tested CLI is pinned to 0.163.0 and newer documentation is not evidence of retroactive capabilities. No supported operator switch that guarantees plaintext on this exact route was established in the inspected source sections. This is a scoped capture investigation, not an audit of the entire Codex project or all possible host integrations.

## Separate proposed case and unresolved route decision

[delegation-unreminded.proposed.json](../experiments/assessment-v2/delegation-unreminded.proposed.json) is a **proposed, unrun** case. It retains the original crate data, full pair-analysis request, observable child output, actual saved report, independent arithmetic check and protected-output requirements. The sole prompt edit removes the explicit sentence telling the parent not to add child style or length constraints. The original case stays unchanged at SHA-256 `26db3a74932254c6c293369c3714f497dc748bbed191652a8d26dd17a628c5db`. Original D2 remains a requirement in the proposed case; removing its reminder does not waive the boundary.

Before affected work, choose an honestly labeled verification route:

1. **Keep native V2 verification pending.** Preserve D2 as unknown while using the already captured child report and saved file to assess output preservation. Require a supported plaintext observability facility before another native retest. This preserves the integration requirement without claiming it has been met.
2. **Approve a distinct explicit-handoff experiment.** The parent writes the actual complete request to a neutral file; a development controller records its bytes and gives exactly those bytes to a separate child conversation, then records the child's public reply and actual deliverables. Offline transport tests must first demonstrate byte preservation and omission detection. This can test whether style guidance inappropriately changes a parent-authored handoff and a child's work. It changes orchestration, so it cannot validate the original native V2 encrypted path, and it must remain a separately named case. Session allocation and owner approval must precede launching it.

Do not manually decrypt, search keys, force a hidden plaintext flag, substitute a root paraphrase for the actual instruction, treat policy inheritance alone as failure, or repeat the same inconclusive native trial. Production implementation and all publication decisions remain on hold.

## Scope and exclusions

Inspected: the two owned r08 rollout files through selected public message/tool metadata fields; the previously exported child messages; original delegation prompt/fixture/check definitions; native guard source; existing controller/RPC and diagnostic records; current official hook/app-server documentation; and the specific router, tool runtime, V2 messaging, hook serialization and public-history sections cited above. Thirteen source files were downloaded from the pinned tag and hashed; downloading a file does not mean its entire contents or transitive dependencies were reviewed.

Excluded: private reasoning and retained-context content; sign-in caches, environment secrets and key material; encrypted message content beyond encoding/length/hash; unrelated local projects; broader Codex storage/decryption implementations, backend services and model internals; all Claude execution; new native hook/model trials; and unrelated source files/tests. Remaining uncertainty includes future host/model plaintext behavior, possible other supported observability routes, and whether any hypothetical replacement route preserves native semantics.
